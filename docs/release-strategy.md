# 一般公開の方針（2026-10-26 の相談から）

まだアプリには反映していない。公開するときの考え方の記録。基本方針は [principles.md](principles.md)。

## 決まったこと

- **進め方**：まず身近な友達に見てもらい、良さそうならより一般に公開する。
- **目的**：ユーザーを増やすこと。使われるツールの開発者になること自体に価値があるので、収益化にはこだわらない。
- **形**：本体は無料で、端末だけで完結する（ファイルから開く＋端末に保存）。有料にするとしても、同期や AI の即答などサーバーが要る機能だけにする。サーバーを持たない限り、運営費はほぼゼロ。
- **言語**：最初は日本語だけ。最終的に多言語対応する。新しく作る機能では、ボタンなどの文言をなるべく一か所にまとめておく。

## 方向は決めたが、正式決定はまだ

- **ライセンス**：AGPL v3 でオープンソースにする方向。一般公開まではライセンスを付けず「All rights reserved」にしておく（AGPL にした版は取り消せないため。2026-10-28）。
  - 誰でも使って改造してよいが、改造版を人に使わせるなら（ネット越しでも）ソースを AGPL で公開する義務がある。囲い込む競合を出しにくくする。
  - 著作権者は本人なので、本人は縛られない。他人の PR を受け入れるときは、権利を譲ってもらう同意（CLA）を取ると、後で有料版などを作る自由が残る。
  - vendor のライブラリ（KaTeX・marked・perfect-freehand）はどれも MIT なので組み合わせられる。
  - 「データを外に送らない」ことをコードで示せるので、信頼につながる。
- 似た形の例：Obsidian（本体無料、同期・公開が有料。ソースは非公開）、Anki・Zotero・Joplin・Logseq（AGPL、同期などが有料）、Excalidraw（MIT、Excalidraw+ が有料）。

## 推奨（未決）

### 想定するユーザー

iPad で数式の多い教材や論文を手書きで読み込む、理系の学生・独学者。MarginNote 4 との違いは「軽い、数式がきれい、AI にすぐ聞ける」。

### AI の費用

- 標準は今の「Claudeに聞く」方式（利用者自身の Claude / ChatGPT アプリに渡す）。運営の費用はかからない。
- アプリ内での即答は、利用者が自分の API キーを入れる方式（BYOK、キーは端末内だけ）を、おまけとして付ける。
- サブスクの枠を外部の Web アプリから使う手段は、今はない（2026-10-26 時点）。

### ユーザーの集め方（お金のかからない順）

- 30 秒くらいのデモ動画（Pencil で数式に書き込み、その場で Claude に聞く）。
- X・Zenn / Qiita・note に開発記事を書く（「iPad だけで作った」という話も含めて）。
- 大学の友達やサークルなど、理系の学生が集まる場所で紹介してもらう。
- 覚えやすい独自ドメインと、1 ページの紹介サイトを用意する。
- アクセス数の計測は、Cookie を使わない軽いもの（Cloudflare Web Analytics など）だけにする。

### 本の著作権

- アプリは本を配らない。利用者が自分のファイルを開くだけ（PDF リーダーと同じ立場）。
- 作らない機能：本を他の人と共有する、本をアプリ側に置いて配る。共有機能を作るなら、書き込みだけを共有し、本文は含めない。
- サンプル本は、自作するか、自由に使えるライセンス（CC BY など）の教材にする。
- 「Claudeに聞く」で送るのは、囲んだ段落だけ。本を丸ごと送る機能は作らない。
- DRM のかかった電子書籍を開けるようにする工夫はしない。

### 問い合わせ・バグ報告

- アプリ内の「ご意見・不具合」から Google フォームを開く。アプリの版と端末の情報は、フォームにあらかじめ入れておく（自動では送らない）。
- GitHub Issues は開発者向けの窓口として並べておく。
- 「個人開発なので返事は不定期」と最初に書いておく。

## 公開前に必要なもの

- 書き込みのバックアップ（書き出し・読み込み）。端末のデータが消える事故への備えで、問い合わせで一番多くなりそうな「書き込みが消えた」への対策にもなる。
- 初回の簡単な案内と、サンプル本。
- 短いプライバシーポリシー（データは端末内だけ。計測は Cookie なし）。
- 簡単な利用規約（無保証。開いたファイルの扱いは利用者の責任）。
- ライセンスの正式決定と LICENSE ファイル。
